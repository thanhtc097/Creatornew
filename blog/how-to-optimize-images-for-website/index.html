The 4 Pillars of Modern Web Image Optimization

To achieve top-tier PageSpeed scores, apply these four principles to every graphic on your site:

  1. Dimension Right-Sizing: Never deliver a 3000px photo to a desktop viewport that only displays it at 800px width. Always resize source images to match their maximum CSS rendering container.
  2. Lossy Perceptual Compression: Compress every JPG, PNG, and WebP file to between 75% and 82% quality. This eliminates redundant data without visible degradation.
  3. Modern Next-Gen Formats: Convert legacy graphics to WebP or AVIF to immediately save 30% or more bandwidth.
  4. Responsive Delivery & Lazy Loading: Serve appropriately scaled image sources based on screen width using the HTML <picture> tag and native loading="lazy" attributes.

Preventing Cumulative Layout Shift (CLS) with Explicit Dimensions

One of the easiest ways to fail Google Core Web Vitals is by omitting width and height attributes in your HTML:

<!-- INCORRECT: Causes layout jumps as the image loads -->
<img src="hero.webp" alt="Creator banner">

<!-- CORRECT: Reserves aspect ratio space in advance -->
<img src="hero.webp" alt="Creator banner" width="1200" height="630" loading="lazy" decoding="async">

By specifying explicit width and height attributes, the browser calculates the aspect ratio before downloading the image, eliminating page shifts.

Frequently Asked Questions

Should I lazy load my above-the-fold hero image?

NO! Never lazy load your Largest Contentful Paint (LCP) element. Above-the-fold hero images should use fetchpriority="high" and preload tags to render as rapidly as possible.

What is the maximum file size a web hero image should have?

Aim to keep your main desktop hero banner under 150 KB to 200 KB. Secondary blog images and thumbnails should ideally stay under 50 KB to 80 KB.

Can SVG replace PNG for web icons?

Yes. For vector logos, simple icons, and interface badges, inline SVG is vastly superior to PNG, offering infinite sharpness at minute file sizes.
